Query Comparison Terms Guide
Performance Metrics
Execution Time (1.0x)

Relative execution time compared to a baseline query. 1.0x = baseline performance. 2.0x = twice as slow. 0.5x = twice as fast.

Example: If Query A shows 1.5x and Query B shows 0.8x, Query B is faster than Query A.
Complexity Score (0-100)

Measures how complex a query is based on:

  • Number of JOINs
  • Subqueries and CTEs
  • Aggregations (GROUP BY, HAVING)
  • Window functions
  • JSON operations
Higher complexity doesn't always mean worse performance, but it often indicates more resource usage.
Memory Usage (%)

Estimated percentage of available memory the query will use. Based on table sizes, join complexity, and sorting operations.

High memory usage can cause performance issues if it exceeds available RAM.
CPU Usage (%)

Estimated percentage of CPU resources the query will consume. Based on computational complexity, sorting, and data processing.

High CPU usage can slow down other operations running on the same server.
Grades & Rankings
Complexity Grade (A-F)

Letter grade based on complexity score:

  • A (0-25): Simple queries, excellent performance
  • B (26-50): Moderate complexity, good performance
  • C (51-75): Complex queries, acceptable performance
  • D (76-90): Very complex, may need optimization
  • F (91-100): Extremely complex, optimization required
Optimization Potential (%)

Estimated percentage of performance improvement possible through optimization.

  • 0-25%: Well-optimized query
  • 26-50%: Minor improvements possible - run detailed analysis
  • 51-75%: Significant optimization opportunities - use Analyze feature
  • 76-100%: Major optimization needed - comprehensive analysis recommended
Tip: For queries with >25% optimization potential, use our detailed Analyze feature for specific recommendations.
Rankings & Comparisons
Performance Ranking

Queries ranked by execution time (fastest first). #1 = fastest query, #5 = slowest query.

Complexity Ranking

Queries ranked by complexity score (simplest first). #1 = simplest query, #5 = most complex query.

Key Differences

Highlights the most significant performance gaps between queries, helping you understand which optimizations will have the biggest impact.

Recommendations

Specific, actionable suggestions for improving query performance based on the comparison analysis.

How to Use This Information
  • Compare execution times to identify the fastest approach
  • Check complexity grades to understand query maintainability
  • Review optimization potential to prioritize improvements
  • Consider resource usage for production environment planning
  • Follow recommendations for specific optimization steps
